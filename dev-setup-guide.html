DEV ENVIRONMENT ONLY

Docker + Nginx + CI/CD Setup Guide

તમારે End-to-End શું શું Configuration કરવું પડશે તેનું સ્ટેપ-બાય-સ્ટેપ ગાઇડ

1

Git 'dev' Branch બનાવો અને Push કરો

આ CI/CD workflow ફક્ત dev બ્રાન્ચ પર જ ટ્રિગર થશે. જો તમારા repo માં dev બ્રાન્ચ નથી, તો લોકલ મશીન પરથી આ કમાન્ડ ચલાવો:

# 1. 'dev' બ્રાન્ચ બનાવો અને સ્વિચ કરો
git checkout -b dev

# 2. નવી ફાઇલો add કરો
git add .

# 3. Commit કરો
git commit -m "chore: setup docker nginx and dev cicd"

# 4. GitHub પર push કરો
git push -u origin dev
2

GitHub Repository Secrets સેટ કરો

જો તમે Dev Server (VPS/Cloud) પર ઓટોમેટિક ડેપ્લોય કરવા માંગો છો, તો GitHub માં આ સિક્રેટ્સ ઉમેરવા પડશે:

જાવ: GitHub Repo → Settings → Secrets and variables → Actions → "New repository secret"

Secret Name શુ વેલ્યુ આપવી? (Value Description) ઉદાહરણ (Example)
DEV_SERVER_HOST તમારા Dev Cloud/VPS સર્વરનો પબ્લિક IP એડ્રેસ 13.233.45.67
DEV_SERVER_USER સર્વરનું SSH યુઝરનેમ ubuntu અથવા root
DEV_SERVER_SSH_KEY તમારા સર્વરની Private SSH Key (~/.ssh/id_rsa) -----BEGIN OPENSSH PRIVATE KEY----- ...
નોંધ: Docker image build અને verify કરવા માટે વધારાના કોઈ સિક્રેટની જરૂર નથી, કારણકે GitHub Actions પોતાની ડિફોલ્ટ secrets.GITHUB_TOKEN વાપરે છે.
3

Dev Server (VPS) પર સર્વર Setup

જો તમારી પાસે AWS EC2, DigitalOcean, Hetzner કે કોઈ પણ Linux VPS છે, તો ત્યાં 1 વાર આ કમાન્ડ રન કરો:

# 1. Server અપડેટ કરો અને Docker ઇન્સ્ટોલ કરો
sudo apt update && sudo apt upgrade -y
curl -fsSL https://get.docker.com | sh

# 2. Docker Compose પ્લગઇન ઇન્સ્ટોલ કરો
sudo apt install docker-compose-plugin -y

# 3. કરંટ યુઝરને docker ગ્રુપમાં એડ કરો (sudo વગર ચલાવવા માટે)
sudo usermod -aG docker $USER
newgrp docker

# 4. પોર્ટ ઓપન કરો (Firewall / AWS Security Group)
# Port 80 (HTTP) -> 0.0.0.0/0 (અને જો SSH હોય તો Port 22)
4

સર્વર પર પ્રોજેક્ટ ક્લોન અને .env ફાઇલ

તમારા Dev સર્વર પર જઈને આ રીતે ફોલ્ડર સેટઅપ કરો:

# સર્વર પર ગિટ પ્રોજેક્ટ ક્લોન કરો (ફક્ત dev બ્રાન્ચ)
git clone -b dev https://github.com/YOUR_USERNAME/task-manager-frontend.git /var/www/dev-frontend
cd /var/www/dev-frontend

# જો કોઈ Environment Variables હોય તો .env.local અથવા .env બનાવો:
nano .env

જો Next.js માં backend API url હોય તો ઉમેરો, જેમ કે: NEXT_PUBLIC_API_URL=http://your-dev-backend-api

5

સર્વર પર Docker Compose ચલાવો

સર્વર પર એક વાર મેન્યુઅલી અથવા CI/CD દ્વારા કન્ટેનર સ્ટાર્ટ કરો:

# 1. કન્ટેનર્સ બિલ્ડ અને બેકગ્રાઉન્ડમાં સ્ટાર્ટ કરો
docker compose -f docker-compose.dev.yml up -d --build

# 2. કંટેનર રન થઈ રહ્યા છે કે નહિ તે ચેક કરો
docker ps

# 3. Nginx અને Next.js ના લાઇવ logs જુઓ
docker compose -f docker-compose.dev.yml logs -f
ચેક કરો: બ્રાઉઝરમાં http://<SERVER_IP> ખોલો. એપ લાઇવ દેખાશે!
Health check ચેક કરવા માટે: http://<SERVER_IP>/health (જવાબ આવશે: healthy).
6

CI/CD કેવી રીતે કામ કરશે? (Workflow Lifecycle)

હવેથી જ્યારે પણ તમે dev બ્રાન્ચમાં કોડ Push કરશો:

  1. GitHub Actions આપોઆપ શરૂ થશે.
  2. Lint & Tests રન કરશે.
  3. Docker Build કરશે અને :dev ટેગ સાથે ઈમેજ તૈયાર કરશે.
  4. સર્વર પર SSH દ્વારા લેટેસ્ટ કોડ પુલ કરીને કન્ટેનર રિસ્ટાર્ટ કરશે.
  5. Main/Production બ્રાન્ચને કશું જ અસર નહિ થાય!
7

મહત્વના કમાન્ડ્સ (Quick Reference)

જરૂરિયાત (Action) કમાન્ડ (Command)
Dev સર્વર સ્ટાર્ટ કરવા docker compose -f docker-compose.dev.yml up -d
Dev સર્વર સ્ટોપ કરવા docker compose -f docker-compose.dev.yml down
નવા ફેરફારો સાથે Rebuild કરવા docker compose -f docker-compose.dev.yml up -d --build
Next.js અને Nginx ના Logs જોવા docker compose -f docker-compose.dev.yml logs -f
Frontend કન્ટેનરના logs ફક્ત જોવા docker logs -f dev-frontend
